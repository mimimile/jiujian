# 地基调研：承重假设核实

> 对应决策 [D9](../决策记录.md)。整个 BYO 订阅模式的地基。
> 调研编排：Workflow `w06rfvlku`（4 agents / ~160k tokens / 9.7 分钟）。关键事实已由主控亲自二次核实（官方 support + legal 页面逐字）。

## 🚦 裁决：YELLOW → 个人非商业用 = GREEN

> **用户意图更新（2026-05-29）**：不打算商业，目标是**更丰富地使用自己的 Claude Code**。这消解了风险 1（ToS）的主要部分——自用即 "ordinary, individual usage of your own Claude Code"，正是官方允许范围；非商业分享的风险也大幅下降。风险 2 也不再是"风险"：6-15 后的月度 Agent SDK 额度本就是 Anthropic 给这类程序化用途的预算，拿来跑股票分析正是"更丰富使用"。残余考量仅取决于分发范围（见 [D10](../决策记录.md)）。

**技术闭环可行；原 YELLOW 的商业地基风险在个人非商业场景下大幅消解。** 本机已验证：claude v2.1.156 已登录订阅 OAuth（用户自己账号），`stock-sdk-mcp@0.2.1` 是真实 stdio MCP server，可用 `--strict-mcp-config --mcp-config` 挂载。"Electron 无头 spawn `claude -p` + 挂股票 MCP + 流式回传" 今天能跑通。

风险不在技术，在**政策 + 经济**，且载重：

### ⚠️ 风险 1：ToS 禁止第三方通过用户订阅凭据路由请求（最高）
官方 [legal-and-compliance](https://code.claude.com/docs/en/legal-and-compliance) 逐字：
> "**Developers** building products or services that interact with Claude's capabilities, including those using the Agent SDK, should use **API key authentication**... Anthropic **does not permit third-party developers to offer Claude.ai login or to route requests through Free, Pro, or Max plan credentials on behalf of their users**."
> "Anthropic reserves the right to take measures to enforce these restrictions and may do so **without prior notice**."
> "Advertised usage limits for Pro and Max plans assume **ordinary, individual usage** of Claude Code and the Agent SDK."

- 灰色地带辩护：仅作为"驱动用户自己本地安装、用户自己触发的 Claude Code = ordinary use"的薄壳驱动，**不做** "Login with Claude" 流程。
- 但 "ordinary, individual usage" 措辞对一个自动化分发应用不利；Anthropic 可无预警封禁。

### ⚠️ 风险 2：配额经济 —— "免费冗余算力"卖点实质失效（高）
官方 [support 15036540](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan) 逐字：
> "Starting **June 15, 2026**, Claude Agent SDK and `claude -p` usage **no longer counts toward your Claude plan's usage limits**."

- 改为独立**月度 Agent SDK 额度**：Pro $20 / Max5x $100 / Max20x $200 / Team Standard $20。
- 额度用尽后超出部分按**标准 API 价**计费；**不滚存**。
- 仅订阅用户有此额度；纯 API key 账户无额度，按量付费照旧。
- **结论**：6-15 后不存在"蹭交互订阅闲置算力"这回事。headless 分析从用户一笔固定月度额度按 API 价扣，一次多工具分析可烧掉可观金额，月中可能被 402 硬停。**原始"蹭免费冗余算力"定位需重新表述**（见 [决策 D2/D10](../决策记录.md)）。

## 调研目标

核实：分发出去的韭见应用，能否可靠地无头驱动终端用户自己的 Claude Code 订阅，并内联挂载 stock-sdk MCP 做股票分析。

## 技术结论（GREEN —— 可行）

### Claude Code 无头接口
- 调用：`claude -p "<prompt>" --output-format stream-json --verbose --include-partial-messages`
- 输出：`text` / `json`（单对象，含 `result/usage/total_cost_usd`）/ `stream-json`（NDJSON 流式事件）。
- 内联挂 MCP：`--mcp-config <file|inlineJSON>`；`--strict-mcp-config` 只加载我们指定的 server（屏蔽用户机器上的杂项 MCP）。
- 工具允许列表：`--allowedTools "ToolSearch,Read"`。
- 鉴权优先级（高→低）：Bedrock/Vertex/Foundry → `ANTHROPIC_AUTH_TOKEN` → `ANTHROPIC_API_KEY` → `apiKeyHelper` → `CLAUDE_CODE_OAUTH_TOKEN` → 订阅 OAuth（Pro/Max 默认）。
- 登录态检测：`claude auth status --json` → `{authenticated, method, plan}`，exit 0/1。
- 备选 `@anthropic-ai/claude-agent-sdk`：**不支持订阅 OAuth，只能用 API key**。故订阅路径只能走 `claude -p` 外壳；API key 路径可用 Agent SDK。

### stock-sdk 数据 / MCP
- 两个包：核心 `stock-sdk@1.10.0`（零依赖、ESM+CJS、Node≥18、无 API key，数据走腾讯 qt.gtimg.cn）；MCP server 是**独立包** `stock-sdk-mcp@0.2.1`（bin `stock-mcp`，stdio，依赖 @modelcontextprotocol/sdk + zod + stock-sdk）。
- 启动：`npx -y stock-sdk-mcp`，或预装后指向绝对 `node dist/index.js`（Electron PATH 被裁剪，推荐绝对路径）。
- 暴露 **~70 个 MCP 工具**：`analyze_stock`/`compare_stocks`/`scan_market`/`get_history_kline`/`get_kline_with_indicators`/`get_fund_flow`/`get_northbound_*`/`get_dragon_tiger_*`/`get_zt_pool` 等，覆盖 A股/港股/美股/基金/期货/期权。
- 注册配置：`{ "mcpServers": { "stock-sdk": { "command": "npx", "args": ["-y","stock-sdk-mcp"] } } }`

### Electron 2026 推荐栈（已拍板，见 D8）
- 构建/开发：**electron-vite**（稳定、Vite 原生、TS、HMR、main/preload/renderer 三目标）。
- 打包：**electron-builder**（DMG/NSIS、macOS 公证、Windows 签名、electron-updater 自更新）。
- UI：**React 18 + TS + shadcn/ui + Tailwind**（本环境有 shadcn registry MCP，Vue 用不了）。配 TanStack Query + Zustand。中文 zh-CN，**红涨绿跌**主题。
- 图表：**KLineChart**（klinecharts，Apache-2.0、零依赖、TS、内置 A股指标；GA 用 9.x，10.x 仍 beta）；ECharts 做辅助分析图。
- 子进程：main 进程 `child_process.spawn`（非 execFile，需流式），`readline` 逐行 `JSON.parse`，`webContents.send` 推渲染层；AbortController 取消 + SIGKILL 兜底；退出时清理子进程。

## 架构

薄壳驱动：应用是用户**自己已安装并登录**的 Claude Code CLI 之上的薄驱动层。应用不处理 Claude 鉴权（交给 `claude auth login`）、不打包 claude 二进制（运行时探测）、不向渲染层暴露 spawn/fs。

```
+-------------------------------------------------------------+
|  RENDERER (React/shadcn, sandbox, ctxIsolation)             |
|  [输入触发] [流式分析面板] [KLineChart 红涨绿跌]            |
+---------------------------↑----------------↓----------------+
      window.api (contextBridge, 仅白名单通道)
+---------------------------↑----------------↓----------------+
|  PRELOAD  api.claude.run/cancel/onEvent, api.system.detect  |
+---------------------------↑----------------↓----------------+
      ipcMain.handle / webContents.send  (Zod 校验)
+---------------------------↑----------------↓----------------+
|  MAIN (Node)                                                |
|  fix-path -> path-resolver(claude.sh/绝对路径) -> 鉴权provider|
|  claude-orchestrator: spawn(claude -p stream-json           |
|    --strict-mcp-config --mcp-config cfg)                    |
|    stdin<-prompt   readline(stdout)->JSON.parse->IPC        |
+-------------------------------↓-----------------------------+
        spawns (作为 claude 的 stdio 子进程)
+-------------------------------↓-----------------------------+
|  claude CLI (用户订阅 OAuth)  --(MCP stdio)-->              |
|  stock-sdk-mcp (~70 工具)  --> 腾讯 qt.gtimg.cn             |
+-------------------------------------------------------------+
```

## 骨架构建计划（M1 最小闭环）

1. 脚手架：electron-vite react-ts 模板（pnpm），pin 已打补丁的 Electron；建 `src/{main,preload,renderer,shared}`；`shared/{ipc-channels,schemas(Zod),types}` 作单一事实源。
2. 安全窗口：`webPreferences { contextIsolation:true, sandbox:true, nodeIntegration:false, preload }`；严格 CSP；自定义协议供渲染资源（不用 file://）；`app.whenReady` 里**第一件事**调 `fix-path()`。
3. 探测：`path-resolver.ts` 经 login-shell `which claude`（处理 claude.sh alias）+ 兜底扫描 + 用户覆盖设置，`--version` 校验；`detect()` 跑 `claude auth status --json` 返回 `{found,version,loggedIn,authMethod,plan}`；UI 出"未找到/未登录"态。
4. preload 桥：`contextBridge` 暴露 `window.api = { system:{detect}, claude:{run,cancel,onEvent} }`，通道名来自 shared；生成 `api.d.ts`；不暴露其他。
5. MCP 配置：`mcp-config.ts` 产出 stock-sdk-mcp 配置到 app-data；优先绝对 node + 绝对 dist/index.js；pin `stock-sdk-mcp@0.2.1`。
6. 编排核心：`claude-orchestrator.ts` —— 每次 AbortController+runId；`spawn(claudeAbs, ['-p','--output-format','stream-json','--verbose','--include-partial-messages','--strict-mcp-config','--mcp-config',cfg,'--allowedTools','ToolSearch,Read'], {shell:false, env:{...PATH:resolved}, signal})`；prompt 经 stdin（Zod 校验）；`readline` 逐行 parse → `webContents.send`；stderr 单独收；close/error 发 done/error；取消 abort→SIGKILL 兜底；before-quit 清理。
7. IPC：`claude.handlers.ts` 注册 `claude:run`/`claude:cancel`，校验 sender + Zod payload。
8. 渲染最小闭环：`useClaudeStream.ts` 订阅事件按 runId 累积；App 一个 shadcn 输入 + 分析按钮 → `api.claude.run`；流式面板 + `api.system.detect` 状态横幅。
9. KLineChart 面板：`KLineChart.tsx` 包 klinecharts，红涨绿跌、zh-CN；蜡烛数据走 `get_history_kline` 结果或 main 里 stock-sdk 直拉经 IPC。闭环完成。
10. 成本/配额遥测：`claude:done` 时显示 `total_cost_usd`/usage；识别 402（额度耗尽）与 ENOENT/127（claude 不在 PATH），给明确文案。**属最小闭环**——配额会硬停。
11. （骨架后）打包：electron-builder 签名公证 DMG + 签名 NSIS；@electron/fuses；GitHub Actions matrix；中国大陆更新镜像。

## 开放决策（需人拍板，见 [决策记录](../决策记录.md) D10）

1. **鉴权策略**：仅订阅 CLI（灰色风险最大）/ 仅 API key（合规但用户付 API 费）/ **两者皆可（可插拔 provider，推荐）**。
2. **分发意图**：自用 / 公开 / 商业。商业或公开发布前应取得 Anthropic 书面澄清。
3. 应用 appId（如 `cn.xxx.jiujian`）、产品名、默认 locale（zh-CN）。
4. 图表数据源：经 claude 的 MCP 结果 vs main 里 stock-sdk 直拉（推荐：图表直拉，分析走 claude）。
5. stock-sdk-mcp 交付：运行时 `npx` vs 预装 + 绝对路径（推荐后者）。
6. 签名账号预算：Apple Developer（$99/yr）+ Azure Trusted Signing；是否需中国更新镜像。
7. 成本控制策略：单次成本上限 / 月度预算预警 / 额度可能耗尽时是否拦截。
8. 首个垂直切片范围：哪个分析（如 `analyze_stock` + `get_history_kline` 蜡烛）+ 哪个市场先端到端打通。
